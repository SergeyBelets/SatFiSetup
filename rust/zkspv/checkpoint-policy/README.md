# Mainnet checkpoint component

This implements specification §5.2 as a local, independently reviewable component.
It is not an activated guest or state contract and does not select a production anchor.

`ValidatedCheckpoint::validate` requires an exact 80-byte checkpoint at a height
divisible by 2016 and at least 10; exactly ten 80-byte predecessors in chronological
order; all ten links through the checkpoint; a positive, non-overflowing target at
or below mainnet's exact powLimit; real checkpoint PoW; and cumulative work at
least equal to the checkpoint's own work. Supplied work already includes that block.
The pre-anchor work and claimed deployment height remain trusted configuration.

The compact guard and decoder are copied **verbatim** from the already qualified
five-correction Citrea source. `generate_compact.py --check` checks the patch chain
and generated bytes. Header decoding, hashing, PoW and block work use upstream's
exact `bitcoin = 0.32.5`; all 16 external dependencies match its lockfile checksums.
There is no new consensus or work arithmetic here.

The factory derives every initial verifier field. Its MTP array uses absolute
height modulo 11, as the pinned verifier does. Current target is the checkpoint's
bits and epoch-start time is its timestamp. Private validated fields cannot be
replaced by a caller. `initialize` adapts them to the native context and checks
both work and the commitment of every context field before creating fork/history
state. The adapter and its `Context` implementation are trusted integration code.
The lower-level fork crate retains its explicit validated-anchor precondition;
future guest integration must use this factory at its input boundary.

Ten predecessors are MTP context only: they are never added to canonical history,
parent lookup or confirmations. Their PoW, earlier historical difficulty, and the
anchor's own MTP are not established by this validation. Future-time policy applies
separately to newly accepted headers against EVM time. There is no host-clock check.

`BitcoinCheckpoint.sol` supplies corresponding constructor-compatible internal
validation, context and descriptor commitments. It reuses the repository's target,
work and hash byte-order helpers. Tests compare it with the unchanged actual
`MainnetHeaderRelay` constructors and the Rust fixture generator. No production
contract imports the new library yet. Descriptor and fork-state commitments must
be authenticated by deployment configuration and the future real proof/state path.

Qualification covers 14 Rust tests in each of debug/release, 8 Solidity tests,
and 24 full native verifier tests (19 retained plus 5 new). New native coverage
starts at actual mainnet height 32256, verifies all 4032 descendants through 36288,
checks every context field against historical fixtures across two retargets, and
replays the complete snapshot. It also compares factory contexts at 40320 and
872928 with independently prepared native contexts and tests exact field binding
and checked chainwork overflow. The original 887-file native checkout is restored.

The three shared vectors are historical test anchors, not authenticated production
choices. New policy/binding code needs independent review. Real guest/proof binding,
production state/adapter integration and bounded proving witnesses remain open.

```sh
python rust/zkspv/checkpoint-policy/generate_compact.py --check
python rust/zkspv/checkpoint-policy/qualify.py \
  --cargo /path/to/cargo-1.88.0 --rustc /path/to/rustc-1.88.0 \
  --rustdoc /path/to/rustdoc-1.88.0 --cargo-home /path/to/prepared-cargo-cache \
  --target-dir /path/to/checkpoint-target --forge /path/to/forge \
  --source /path/to/pinned-full-citrea-checkout --archive /path/to/pinned-citrea.tar.gz \
  --native-target-dir /path/to/prepared-native-target
```

`report.json` and `evidence/` bind source, dependency, compiler and log hashes.
All commands run offline, without deployment, node RPC, public transactions or
hosted proving services. Component PASS never changes the overall production gate.
