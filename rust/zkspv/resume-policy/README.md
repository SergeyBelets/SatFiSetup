# Bounded resume witnesses — experimental V2

This NEW_INTEGRATION component removes full-history replay from the transition
**verifier input**, while retaining the same pinned Bitcoin verifier, checkpoint
factory, canonical history encoding, fork choice and 100/101 halt policy.
It is not a real guest/proof, activated state contract, production archive service
or qualified migration. New index/LCA/state logic requires independent review.

## Why V2

V1 commits known entries through a sequential hash chain. That binds order but
cannot supply bounded membership/non-membership proofs for an arbitrary old
context. V2 adds a sparse 256-bit index keyed by the raw block hash and retains
a separate ordered admission commitment. Its state commitment is deliberately
incompatible with V1. V1 sources/evidence and journal/decoder remain unchanged.
There is no automatic conversion of an accepted V1 root, deployment switch or
proof acceptance. V2 journal/EVM binding is still pending.

An indexed entry binds raw header, height, cumulative work, commitment of **all**
native context fields, and its branch-history root. In particular the stored
`current_target_bits` survives an epoch boundary; it is never reconstructed from
the old tip's raw bits. Authentication comes from the externally accepted V2 state
commitment, not from the index root or serialized context supplied by a prover.

## Verification

`resume(expected_commitment, before, headers, witnesses, verifier)` has no archive
argument and never replays old consensus transitions. It authenticates the whole
before-state, then each step proves either exact known-header inclusion (no-op),
or absence of a new hash plus inclusion of its parent and current head. The
unchanged pinned verifier validates the new header. An empty-leaf proof permits
appending its canonical leaf to its parent's history without overwriting history.

Only a strictly heavier candidate requires an LCA witness. Both history roots
must contain the same header at the common height. If neither tip is that header,
the two immediately following headers must differ and both must name it as their
parent. Thus an earlier common ancestor cannot be presented as the last common
ancestor to create a false deep-reorg halt. This relies on the inductively verified
connected histories committed by these roots; it is not a claim about arbitrary
unverified trees. Equal work retains the head, shorter/heavier branches may win,
and losing contexts remain indexed for later continuation.

Every unique admission updates both the indexed root and ordered log, including
the halt candidate. At depth 101 the last safe prefix is retained and later items
are ignored. Invalid batches produce no outcome. Time summaries exclude restored
history and exact duplicates, include new losing branches and the halt candidate,
and use the existing time-policy module. Input batch commitment includes ignored
suffix bytes without claiming to validate them. Pure overlap returns `NoChange`.
The expected before commitment must be authenticated externally. Observations
never supplied to the program remain outside its completeness guarantees (§15.11).

## Exact encodings and resource limits

All hashing uses the unchanged fork-policy framed SHA256:
`SATOSHIFI_FORK_V1\0 || u32BE(domain length) || domain || (u64BE(part length) || part)*`.
The generated `history.rs` is byte-for-byte V1, and `bindings.rs` preserves its
parsing/scope/leaf/canonical-root function bodies. `generate_reuse.py --check`
checks the original hashes and regenerated bytes.

The index key is the 32 raw hash bytes interpreted as unsigned big endian. Proofs
are leaf-to-root, consuming bit zero first. Empty leaf domain is
`resume-index-empty-v2`; parent is `resume-index-node-v2(depth:u16BE,left,right)`.
Exactly 256 siblings are required. Entry leaf is `known-header-v2(scope,raw80,
height:u64BE,work32,contextCommitment32,branchHistoryRoot32)`. The context commitment
is the existing `citrea-LatestDaState-v1` encoding. Canonical history paths remain
exactly 64 siblings and retain the existing Solidity-compatible leaf/root encoding.

Initial ordered log is `resume-anchor-v2(checkpointDescriptor,entryLeaf)`; each
new entry produces `resume-entry-v2(previousLog,blockHash,entryLeaf)`. State is
`resume-state-v2(checkpointDescriptor,anchor,anchorHeight:u64BE,knownRoot,knownLog,
knownCount:u64BE,canonicalRoot,head,height:u64BE,work32,tipTime:u32BE,haltDigest)`.
Halt/running digest uses the unchanged fork-policy encoding. State commitment
binds admission order even if a permutation would leave the map and tip identical.

The strict witness codec uses a 32-byte right-zero-padded
`SATOSHIFI_RESUME_WITNESS_V2` domain, a u16BE item count, and one-byte variant tags.
Tag 0 is an entry plus its 256 siblings. Tag 1 is an absence path, parent opening,
head opening, 64-sibling empty-history path and a 0/1 LCA flag. LCA contains the
common membership, the candidate's 64 common siblings and a 0/1 children flag;
when present, two child memberships follow. Membership is height:u64BE, raw80,
then 64 hashes. Entry is raw80, context124, historyRoot32. Context consists of
hash32, height:u64BE, work32, bits:u32BE, epochTime:u32BE, and 11 u32BE timestamps.
Path lengths are implicit and exact. Unknown tags/flags, truncation, oversized
counts and trailing data are rejected. Size/count checks precede allocations.

| Bound | Value |
| --- | --- |
| Submitted items / raw-header byte budget | 64 / 5120 bytes |
| Maximum path hashes per step | 1088 |
| Maximum wire payload per step | 35,555 bytes |
| Maximum complete witness wire | 2,275,554 bytes |
| One append witness including envelope | 31,317 bytes |
| Consensus calls in bounded verification | One per unique new processed header |

These bounds cover witness decoding and the resume kernel. They do not establish
zkVM cycle cost, peak whole-process memory, proving/wrapping latency or economics.
Fixed paths are bounded, not optimally compressed; multiproofs remain a possible
future optimization after review. The raw-byte budget is an explicit V2 input
limit, also applying to ignored suffix bytes.

## Archive and evidence

`Archive` is a local persistent-node store and witness builder. It retains the
complete admitted header log, contexts and branch roots and can be rebuilt from
that log. Construction and retention still scale with history. It checks generated
witnesses and rolls back nodes, roots and entries on errors. Its trusted consensus
adapter may run during both construction and checking; these host calls are not
counted as bounded-verifier calls. Durable disk storage, pruning/availability and
operational recovery orchestration remain unimplemented.

20 Rust tests run in debug and release, including 200 transitions compared with
V1, 100/101, false-LCA rejection, context/path tampering, order binding, codec
limits and unchanged append witness size after 8/512 historical headers. Synthetic
graph callbacks do not qualify Bitcoin PoW. Four new full-native tests run with
28 retained tests. They process 4032 historical descendants and resume at both
retargets with one new-header verification and 31,317 witness bytes; they also
check duplicate overlap, archive rebuild and rejection of invalid PoW/context.
Python independently checks wire, indexed roots and V2 state encoding.

```sh
python rust/zkspv/resume-policy/generate_reuse.py --check
python rust/zkspv/resume-policy/qualify.py \
  --cargo /path/to/cargo-1.88.0 --rustc /path/to/rustc-1.88.0 \
  --rustdoc /path/to/rustdoc-1.88.0 --cargo-home /path/to/prepared-cargo-cache \
  --target-dir /path/to/resume-target --source /path/to/pinned-full-citrea-checkout \
  --archive /path/to/pinned-citrea.tar.gz --native-target-dir /path/to/prepared-native-target
```

Qualification is offline and restores the original 887-file native checkout.
No Solidity production files, guest image, real proof, deployment or RPC are
created by this component. Root production gates remain closed.
