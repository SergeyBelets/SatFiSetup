# Конкурирующая финализация в локальной EVM

Стенд выполняет байткод небольшого тестового контракта с интерфейсом FROSTCoordinator. Он проверяет порядок транзакций, квитанции EVM, ожидание глубины и восстановление реальных SQLite-журналов signer-agent. Контракт сохраняет агрегированную подпись как данные. Криптографическую проверку FROST и финальность публичного Ethereum этот тест не выполняет.

Для запуска нужны Python 3.11+, зависимости signer-agent с группой `evm-test`, Node.js и локальная установка npm-пакета `solc@0.8.30`. Проверенная конфигурация использует web3 7.16.0, eth-tester 0.13.0b1 и py-evm 0.12.1b1. Компиляция идёт через IR для Prague, оптимизатор включён, runs=1. После установки зависимостей стенд работает без сети.

Из каталога `signer-agent`, с активным тестовым окружением Python:

```sh
PYTHONPATH="$PWD" NODE_PATH="/absolute/path/to/node_modules" python tests/integration_fixtures/finalize/run.py
```

Скрипт печатает три JSON-записи с номерами блоков, индексами транзакций, их хешами, расходом газа и состояниями журналов. В первых двух записях совпадает подпись победителя, результат проверки после перезапуска — `FINALIZED`, следующая независимая транзакция того же EOA проходит с очередным nonce. В третьей записи байты подписи различаются, участник получает `RECOVERY_REQUIRED`, следующая транзакция отсутствует. Код возврата 0 означает, что все assertions прошли. Для каждого сценария создаются новая цепочка Py-EVM и временный каталог участника.
