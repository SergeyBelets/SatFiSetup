# Проверка финализации исторического FROST

Из этого каталога с активным окружением Python и установленными зависимостями signer-agent, включая группу `evm-test`, выполните

```sh
PYTHONPATH=../../../.. python -B run.py
```

Стенд берёт байткод FROSTVerifier и FROSTCoordinator из каталога `rust/zkspv/deposit-integration/evidence/run-04/consumer-artifacts` распакованного выпуска. Параметр `--artifacts` принимает другой каталог с теми же двумя файлами. Для каждого прогона создаются отдельная цепочка Py-EVM и временные журналы SQLite. Запуск работает без сети и компиляции контрактов.

Два участника регистрируют тестовые публичные доли, публикуют обязательства по nonce и отправляют проверяемые доли подписи. Контракт проверяет обе доли, библиотека coincurve независимо проверяет агрегированную подпись BIP340. Пока сессия открыта, попытка финализации с испорченной подписью получает квитанцию со статусом 0.

Две JSON-строки описывают конкурирующие транзакции с одной подписью в общем блоке и в соседних блоках. Проверки охватывают preflight SDK, квитанции обеих транзакций, ожидание глубины, повторное открытие журналов и отправку следующей независимой транзакции с очередным nonce. Доли подготовлены локально для вызова `createSession`. Сетевой DKG, `createSessionFromDKG` и консенсусная финальность публичного Ethereum требуют отдельного прогона.
